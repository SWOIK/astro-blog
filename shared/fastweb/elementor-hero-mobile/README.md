# Fastweb Scroll Hero สำหรับ WordPress + Elementor

Hero แอนิเมชันที่ **ใช้การ scroll ควบคุม** พร้อมข้อความและปุ่ม ทำเป็นโค้ดชุดเดียววางใน Elementor HTML widget
ไม่มี library ไม่มีไฟล์ภายนอก ไม่มี request เพิ่ม (รูป "นัดคุย" ฝังเป็น data URI ขนาดประมาณ 1.5 KB)
ไฟล์ `hero-mobile.html` ขนาดประมาณ 32 KB (gzip ประมาณ 11 KB ก่อน minify)

## แอนิเมชันทำงานอย่างไร

กระเบื้องพื้น, pixel "Fw" และเศษวงกลม **เป็นอนุภาคชุดเดียวกัน (593 ชิ้น = จำนวนช่องของโลโก้)** เปลี่ยนแค่รูปร่างตามการ scroll

1. ตอนเริ่ม: เป็นพื้นกระเบื้องสีเข้มโทนน้ำเงิน (สีวัดจากคลิป) กระเบื้องแต่ละแผ่นแบ่งเป็นช่องเล็กๆ ตามขนาดของมัน
2. scroll ลง: กระเบื้องลอยขึ้น รวมกลางจอ สว่างขึ้นเป็นสีน้ำเงินของโลโก้ แล้วเรียงเป็น pixel "Fw" (พื้นไม่เหลืออยู่ซ้ำอีกชุดหนึ่ง)
3. ค้างโลโก้ พร้อมแสง glow
4. scroll ต่อ: โลโก้แตกกระจายเป็นวงกลม (เศษบางส่วนสีขาว)
5. scroll ต่ออีก: เศษวงกลมตกกลับเป็นกระเบื้องแผ่นเดิมของตัวเอง ผ่านสีน้ำเงิน/เทา แล้วหรี่ลงเป็นสีพื้น ครบแล้วหน้าเว็บเลื่อนต่อไปส่วนถัดไปตามปกติ

เลื่อนย้อนกลับขึ้นได้ ทุกอย่างย้อนกลับตามการเลื่อน

## วิธีใช้ใน Elementor

1. สร้าง Container ใหม่ ตั้ง **Content Width = Full Width** และ padding = 0
2. ลาก **HTML widget** ใส่ แล้ววางโค้ดจาก `hero-mobile.html` ทั้งไฟล์
3. แท็บ Advanced ของ widget ตั้ง margin/padding = 0
4. ที่ Container แท็บ Advanced > Layout ตั้ง **Overflow = Default** (ห้ามเป็น Hidden เพราะ `position: sticky` จะพัง)
5. header ไม่อยู่ในโค้ดนี้ ใช้ header ของ Elementor ตามเดิม
6. ตั้ง `--swk-lead-top` ให้ข้อความไม่ชน header: ถ้า header ลอยทับ hero ใช้ `99px` (ค่าเริ่มต้น) ถ้า header อยู่เหนือ hero ใช้ประมาณ `24px`

ตอนนี้ออกแบบสำหรับมือถือ (ดูหัวข้อ "เดสก์ท็อปและแท็บเล็ต" ด้านล่าง) ถ้าหน้าเดียวกันมีผู้ชมบนเดสก์ท็อป ให้รอดีไซน์ส่วนนั้นก่อน

## เปลี่ยนข้อความ ลิงก์ และ tag

ข้อความทั้งหมดเป็น HTML ในไฟล์ จัดสไตล์ด้วย class **ไม่ผูกกับชื่อ tag** จึงเปลี่ยน tag ได้โดยแก้แค่ชื่อ tag เปิดและปิด

| ส่วน | โค้ด | ค่าเริ่มต้น |
|---|---|---|
| ข้อความนำ | `<div class="swk-lead">` | `div` เปลี่ยนเป็น `p` ฯลฯ ได้ |
| หัวข้อหลัก | `<h1 class="swk-title">` | `h1` เปลี่ยนเป็น `h2` ได้ (ควรมี h1 แค่ตัวเดียวต่อหน้า) |
| บรรทัดบน / ล่างของหัวข้อ | `swk-t1` สี `#ffffff` / `swk-t2` สี `#98a1b3` | |
| ปุ่มเริ่มโปรเจกต์ | `swk-btn--primary` พื้น `#126ef5` ตัวหนังสือและไอคอน `#ffffff` | ลิงก์ `#contact` |
| ปุ่มดูผลงาน | `swk-btn--light` พื้น `#ffffff` ตัวหนังสือและไอคอน `#050506` | ลิงก์ `#work` |
| ชิป "นัดคุย" | `swk-chip` | ลิงก์ `#contact` |

- ลิงก์ `#contact`, `#work` เป็นค่าตัวอย่าง แก้เป็นหน้าจริงของคุณ
- ไอคอนลูกศร pixel ใช้จากไฟล์ `Icon.svg` โดยกำหนดครั้งเดียวด้วย `<symbol id="swk-arrow">` สีเปลี่ยนตามสีตัวหนังสือของปุ่มอัตโนมัติ (`fill: currentColor`)
- รูปในชิป "นัดคุย": ฝังเป็น data URI 56x56 เปลี่ยนเป็นรูปจากคลัง Media ได้ โดยแทนที่ค่า `src` ถ้าเปลี่ยนเป็นไฟล์ใหญ่ ควรกำหนดขนาดเป็นสองเท่าของที่แสดง (56x56) รูปแสดงเป็นขาวดำตามคลิป ถ้าต้องการรูปสีให้ตั้ง `--swk-avatar-filter: none`
- ฟอนต์ใช้ฟอนต์ของเว็บไซต์ (`font-family: inherit`) ไม่โหลดฟอนต์เพิ่ม ถ้าต้องการฟอนต์เฉพาะตั้ง `--swk-font`

## ตัวแปรที่ปรับได้ (ใน `.swk-hero`)

| ตัวแปร | ความหมาย | ค่าเริ่มต้น |
|---|---|---|
| `--swk-len` | ระยะ scroll ที่ใช้เล่นแอนิเมชัน | `300svh` |
| `--swk-top` | ความสูง header ถ้า header ติด sticky ด้านบน | `0px` |
| `--swk-lead-top` | ตำแหน่งข้อความนำจากขอบบน | `99px` |
| `--swk-bottom` | ระยะปุ่มจากขอบล่าง | `40px` |
| `--swk-accent` | สีปุ่มหลัก | `#126ef5` |

ในส่วน `<script>`: อาร์เรย์ `LOGO` (34x42 ช่อง แก้ได้ทีละช่อง `.` ว่าง, `#` น้ำเงิน, `+` น้ำเงินอ่อน), `BASE` (ขนาดโลโก้ ตำแหน่ง วงกลม พื้น), `C_*` และ `FLOOR_*` (สีอนุภาคและกระเบื้อง) และค่าไทม์ไลน์ `FORM_*`, `BURST_*`, `BACK_*`

## เดสก์ท็อปและแท็บเล็ต

แนะนำให้ใช้ **ไฟล์เดียวและ HTML widget เดียว** แล้วแยกส่วนที่ต่างกันดังนี้

- **ตำแหน่งข้อความ ปุ่ม ขนาดตัวอักษร:** เขียน CSS `@media (min-width: 768px)` และ `(min-width: 1024px)` ในไฟล์เดียวกัน
- **ขนาดและตำแหน่งโลโก้ วงกลม พื้น:** ใส่ค่าที่ต่างใน `OVERRIDE.tablet` และ `OVERRIDE.desktop` ในสคริปต์ (เตรียมโครงไว้แล้ว ตอนนี้ว่างอยู่)
- เหตุผล: Elementor "Hide on device" ซ่อนด้วย CSS เท่านั้น HTML และสคริปต์ของ widget ที่ซ่อนยังถูกส่งและรันอยู่ ถ้าแยกสคริปต์ต่ออุปกรณ์จะส่งเอนจินแอนิเมชันซ้ำหลายชุด

ถ้าดีไซน์เดสก์ท็อปต่างจากมือถือมากจนโครง HTML ต่างกัน ก็ยังควรใช้เอนจินแอนิเมชันชุดเดียวกัน (ส่วน `<script>`) ส่งคลิปและเฟรมดีไซน์ของเดสก์ท็อป/แท็บเล็ตมาได้เมื่อพร้อม

## เรื่อง PageSpeed / SEO

- ข้อความ หัวข้อ ปุ่ม และลิงก์ **อยู่ใน HTML ที่เซิร์ฟเวอร์ส่งมา** ไม่ได้ถูกสคริปต์สร้างทีหลัง Google อ่านได้เหมือนการใช้ widget ของ Elementor
- `h1` เป็นองค์ประกอบ LCP ส่วน canvas ไม่นับเป็นองค์ประกอบ LCP และใส่ `aria-hidden` เพราะเป็นของตกแต่ง
- ไม่มี request เพิ่ม ไม่โหลดฟอนต์และรูปภายนอก
- วาดเฉพาะตอน scroll และหยุดเมื่อพ้นจอ (`IntersectionObserver`) จำกัด devicePixelRatio ไม่เกิน 2
- ผู้ใช้ที่เปิด `prefers-reduced-motion` จะเห็นภาพโลโก้นิ่งแทน และความสูง hero ลดเหลือ 1 หน้าจอ
- ถ้าปิด JavaScript ข้อความและปุ่มยังแสดงอยู่

## ข้อควรระวัง

- ปลั๊กอิน cache/optimize (WP Rocket, LiteSpeed, Autoptimize) ที่มีตัวเลือก **Delay JavaScript** ให้เพิ่มข้อยกเว้นให้สคริปต์นี้ (เช่นคำว่า `swk-hero`) ไม่เช่นนั้นแอนิเมชันจะเริ่มช้า การ minify ปกติไม่มีปัญหา (โค้ดใช้ `;` ครบและไม่มีคอมเมนต์ `//`)
- ถ้า theme มี `overflow: hidden` ที่ `body` หรือ wrapper ครอบทั้งหน้า sticky จะไม่ทำงาน ให้ปรับ CSS ส่วนนั้น
- ถ้าเว็บมีหลายภาษา (TH / EN / LO) ข้อความใน HTML widget ต้องแก้ในหน้าแต่ละภาษาเอง ปลั๊กอินแปลภาษาไม่จัดการข้อความใน widget นี้ให้แบบอัตโนมัติเท่ากับ widget มาตรฐานของ Elementor
- บนเบราว์เซอร์เก่าที่ไม่รู้จักหน่วย `svh` จะ fallback เป็น `vh`
- ผลทดสอบทำใน Chromium (จำลองมือถือ) ยังไม่ได้ทดสอบบน Safari จริงหรือบน Elementor จริง ควรเปิดดูบนมือถือจริงก่อนขึ้นเว็บ
