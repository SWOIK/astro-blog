# Fastweb Scroll Hero สำหรับ WordPress + Elementor (มือถือ / แท็บเล็ต / เดสก์ท็อป)

Hero แอนิเมชันที่ **ใช้การ scroll ควบคุม** พร้อมข้อความและปุ่ม ทำเป็นโค้ดชุดเดียววางใน Elementor HTML widget
ไม่มี library ไม่มีไฟล์ภายนอก ไม่มี request เพิ่ม (รูป "นัดคุย" ฝังเป็น data URI ขนาดประมาณ 1.5 KB) ฟอนต์ใช้ที่เว็บไซต์มีอยู่แล้ว (ดูหัวข้อ "ฟอนต์")
ไฟล์ `hero.html` ขนาดประมาณ 57 KB (gzip ประมาณ 18 KB ก่อน minify)

## ชุดไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `hero.html` | โค้ดทั้งหมด (CSS + HTML + สคริปต์) วางใน Elementor HTML widget |
| `README.md` | คู่มือนี้ |

## หน้าจอที่รองรับ

| ความกว้างหน้าจอ | องค์ประกอบ | ความยาวการเลื่อนเริ่มต้น |
|---|---|---|
| ต่ำกว่า 768px (มือถือ) | แอนิเมชันแบบมือถือ ข้อความเรียงแนวตั้ง | 300svh |
| 768 - 1023px (แท็บเล็ต) | แอนิเมชันแบบมือถือ แต่โลโก้ FW เล็กลงและเยื้องไปทางขวา (ไม่ทับตัวหนังสือ) พื้นกระเบื้องด้านซ้ายเลือนลางแบบเดสก์ท็อป ปุ่มกะทัดรัดชิดซ้ายเหมือนเดสก์ท็อป | 300svh |
| 1024px ขึ้นไป (เดสก์ท็อป) | แอนิเมชันแบบเดสก์ท็อป (ยาวกว่า มีฉาก Nav / Card / หน้าเว็บ) ข้อความอยู่ซ้ายล่างและขวาบนตามดีไซน์ 1440x900 | 500svh |

ใช้ HTML widget **ตัวเดียว** สำหรับทุกอุปกรณ์ สคริปต์เลือกแบบอัตโนมัติตามความกว้างหน้าจอ และสร้างใหม่เมื่อย่อขยายหน้าต่างข้ามจุดเปลี่ยน
อย่าซ่อน/แสดง widget แยกตามอุปกรณ์ด้วย "Hide On Device" เพราะ HTML และสคริปต์ของ widget ที่ซ่อนยังถูกส่งและรันอยู่ ทำให้ส่งโค้ดซ้ำโดยไม่จำเป็น

## แอนิเมชันทำงานอย่างไร

กระเบื้องพื้น, pixel "Fw" และเศษที่แตกกระจาย **เป็นอนุภาคชุดเดียวกัน (593 ชิ้น = จำนวนช่องของโลโก้)** เปลี่ยนแค่รูปร่างตามการ scroll

**มือถือและแท็บเล็ต**

1. ตอนเริ่ม: พื้นกระเบื้องสีเข้มโทนน้ำเงิน (สีวัดจากคลิป) กระเบื้องแต่ละแผ่นแบ่งเป็นช่องเล็กตามขนาดของมัน
2. scroll ลง: กระเบื้องลอยขึ้น รวมกลางจอ สว่างเป็นสีน้ำเงินของโลโก้ แล้วเรียงเป็น pixel "Fw"
3. ค้างโลโก้ พร้อมแสง glow
4. scroll ต่อ: โลโก้แตกกระจายเป็นวงกลม
5. scroll ต่ออีก: เศษวงกลมตกกลับเป็นกระเบื้องแผ่นเดิมของตัวเอง

**เดสก์ท็อป (ไทม์ไลน์ 13 วินาที ตามคลิป hero-desktop)**

| วินาที | เหตุการณ์ |
|---|---|
| 0.0 - 0.9 | พื้นกระเบื้อง (กำแพงอิฐเอียงตามมุมมอง) |
| 0.9 - 2.3 | กระเบื้องลอยขึ้น รวมกัน แล้วเรียงเป็น Fw ที่ฝั่งขวา |
| 2.3 - 3.15 | ค้างโลโก้ พร้อม glow |
| 3.15 - 3.65 | แตกกระจายเป็นเศษทั่วจอ |
| 3.95 - 4.7 | เศษเปลี่ยนเป็นสีเทา วิ่งเข้ามารวมเป็นแถบ Nav |
| 4.7 - 6.1 | Nav (wireframe) เคอร์เซอร์เลื่อนเข้ามา คลิกเมนู (5.85) |
| 6.1 - 8.1 | Card เคอร์เซอร์คลิกปุ่ม (7.55) ปุ่มเปลี่ยนเป็นสีน้ำเงิน |
| 8.1 - 9.9 | หน้าเว็บ (wireframe) เคอร์เซอร์คลิกปุ่ม (9.4) |
| 9.9 - 11.4 | หน้าเว็บย่อและเอียง ซ้อนกับ Nav และ Card |
| 11.4 - 12.0 | wireframe แตกเป็นเศษสีเทา/น้ำเงิน |
| 12.0 - 12.35 | เศษตกกลับเป็นกระเบื้องพื้นแผ่นเดิม แล้วนิ่งจนจบ |

เลื่อนย้อนกลับขึ้นได้ ทุกอย่างย้อนกลับตามการเลื่อน (ตำแหน่งเคอร์เซอร์ สถานะปุ่ม ฯลฯ คำนวณจากเวลา)

ภาพพื้นหลังเดสก์ท็อปวาดใน "พื้นที่ดีไซน์ 1920x1080" แล้วครอบเต็มจอแบบ `object-fit: cover` เหมือนคลิปต้นฉบับ
จอที่แคบกว่า 16:10 จะชิดขวา เพื่อให้ฝั่งขวาที่มีโลโก้และ wireframe ไม่โดนตัด

## วิธีใช้ใน Elementor

1. สร้าง Container ใหม่ ตั้ง **Content Width = Full Width** และ padding = 0
2. ลาก **HTML widget** ใส่ แล้ววางโค้ดจาก `hero.html` ทั้งไฟล์
3. แท็บ Advanced ของ widget ตั้ง margin/padding = 0
4. ที่ Container แท็บ Advanced > Layout ตั้ง **Overflow = Default** (ห้ามเป็น Hidden เพราะ `position: sticky` จะพัง)
5. header ไม่อยู่ในโค้ดนี้ ใช้ header ของ Elementor ตามเดิม
6. ตั้ง `--swk-lead-top` ให้ข้อความไม่ชน header: ถ้า header ลอยทับ hero ใช้ค่าเริ่มต้น (มือถือ 99px, แท็บเล็ต 120px, เดสก์ท็อป 149px) ถ้า header อยู่เหนือ hero ใช้ประมาณ `24px`

## พื้นกระเบื้อง

ลายพื้นวัดจากรูปอ้างอิงของเดสก์ท็อป ทุกหน้าจอเรียงแบบเดียวกัน (กระเบื้องกว้างเท่ากันในแถว เยื้องเป็นอิฐ ระยะห่างสม่ำเสมอ) บนมือถือและแท็บเล็ตขนาดกระเบื้องคิดจากความกว้างจอ และแถวถูกเดินจากขอบล่างขึ้นไปตามความสูงกระเบื้อง ระยะห่างจึงสวยเท่ากันทุกขนาดจอ

- **ไม่เรียงเป๊ะ:** กระเบื้องแต่ละแผ่นเยื้องขึ้นลงจากแนวแถว (`jy`) เยื้องซ้ายขวา (`jx`) และแถวคดเป็นคลื่นเบาๆ (`wv`) ให้ดูบิดเบี้ยวแบบธรรมชาติ ทั้งแนวตั้งและแนวนอน
- **ขนาดไล่ตามความลึก:** แถวไกลเล็กและชิดกัน แถวใกล้ใหญ่ ห่างกว่า มุมกระเบื้องโค้งมน
- **ความสว่าง:** ส่วนใหญ่มืด มีกระเบื้องสว่างโดดเพียงส่วนน้อย (`vp` ยิ่งสูงยิ่งมีน้อย)
- **จางหายตามตำแหน่ง (`mask`):**
  - เดสก์ท็อป: กระเบื้องเด่นที่ขวาล่าง จางหายไปทางด้านบน (ชิ้นบนสุดเลือนลางอยู่แถวปุ่ม "นัดคุย") ด้านซ้ายมืดเพื่อให้ตัวหนังสืออ่านง่าย และขอบขวาจางเล็กน้อย
  - แท็บเล็ต: ด้านซ้ายเลือนลางแบบเดสก์ท็อป (ตัวหนังสือหลักอยู่ซ้ายล่าง) ด้านขวาปกติ จางด้านบนเล็กน้อย กระเบื้องและวงกลมที่แตกกระจายทับตัวหนังสือได้
  - มือถือ: จางด้านบนและด้านซ้ายเล็กน้อย
- ตอนอยู่นิ่ง กระเบื้องแต่ละแผ่นถูกวาดเป็นแผ่นเดียว ตอนเริ่มเคลื่อนที่จึงค่อยแตกเป็นช่องเล็กตามเดิม
- **wireframe บนเดสก์ท็อปไม่ชนปุ่ม "นัดคุย":** ถ้าหน้าต่างเตี้ยจนภาพถูกครอบขึ้นไปชน สคริปต์จะย่อ wireframe และเลื่อนลงอัตโนมัติ ให้เว้นจากปุ่มอย่างน้อย 28px และไม่ล้นขอบล่าง หน้าจอปกติไม่ถูกแตะ

## เล่นวนอัตโนมัติแทนการ scroll

ถ้าต้องการให้เดสก์ท็อป (หรือทุกอุปกรณ์) เล่นวนเองเหมือนวิดีโอ แทนที่จะให้ scroll ควบคุม ให้แก้บรรทัดแรกของสคริปต์:

```js
var DRIVE = "loop";
```

สคริปต์จะย่อ hero เหลือ 1 หน้าจอเอง ไม่ต้องแก้ CSS การเล่นวนจะหยุดเมื่อ hero พ้นจอ และไม่เล่นถ้าผู้ใช้เปิด reduced-motion

## เปลี่ยนข้อความ ลิงก์ และ tag

ข้อความทั้งหมดเป็น HTML ในไฟล์ จัดสไตล์ด้วย class **ไม่ผูกกับชื่อ tag** จึงเปลี่ยน tag ได้โดยแก้แค่ชื่อ tag เปิดและปิด

| ส่วน | โค้ด | ค่าเริ่มต้น |
|---|---|---|
| ข้อความนำ | `<div class="swk-lead">` | `div` เปลี่ยนเป็น `p` ฯลฯ ได้ |
| หัวข้อหลัก | `<h1 class="swk-title">` | `h1` เปลี่ยนเป็น `h2` ได้ (ควรมี h1 แค่ตัวเดียวต่อหน้า) |
| บรรทัดบน / ล่างของหัวข้อ | `swk-t1` สี `#ffffff` / `swk-t2` สี `#98a1b3` | |
| ปุ่มเริ่มโปรเจกต์ | `swk-btn--primary` พื้น `#126ef5` ตัวหนังสือและไอคอน `#ffffff` | ลิงก์ `#contact` |
| ปุ่มดูผลงาน | `swk-btn--light` พื้น `#ffffff` ตัวหนังสือและไอคอน `#050506` | ลิงก์ `#work` |
| ชิป "นัดคุย" | `swk-chip` | ลิงก์ `#contact` |

- ลิงก์ `#contact`, `#work` เป็นค่าตัวอย่าง แก้เป็นหน้าจริงของคุณ
- ไอคอนลูกศร pixel ใช้จาก `Icon.svg` โดยกำหนดครั้งเดียวด้วย `<symbol id="swk-arrow">` สีเปลี่ยนตามสีตัวหนังสือของปุ่มอัตโนมัติ (`fill: currentColor`)
- รูปในชิป "นัดคุย": ฝังเป็น data URI 56x56 เปลี่ยนเป็นรูปจากคลัง Media ได้โดยแทนที่ค่า `src` รูปแสดงเป็นขาวดำตามคลิป ถ้าต้องการรูปสีให้ตั้ง `--swk-avatar-filter: none`
- ขนาดตัวอักษรและตำแหน่งของแต่ละอุปกรณ์อยู่ใน `@media` ท้ายส่วน `<style>` (แท็บเล็ต `768-1023px`, เดสก์ท็อป `1024px` ขึ้นไป)

## ฟอนต์

ใช้ **IBM Plex Sans Thai** น้ำหนัก 400 (ข้อความ หัวข้อ) และ 600 (ปุ่ม) ตามดีไซน์ ขนาดตัวอักษรวัดเทียบกับคลิปด้วยฟอนต์ตัวนี้ ความกว้างข้อความตรงกันภายใน 0.5%

| ส่วน | มือถือ | แท็บเล็ต | เดสก์ท็อป |
|---|---|---|---|
| ข้อความนำ | 15px | 18px | 20px |
| หัวข้อหลัก | 35px | 40-60px | 62px |
| ชิป "นัดคุย" | 13px | 15px | 13px |
| ปุ่ม | 13px | 16px | 14px |

สคริปต์ **ไม่โหลดฟอนต์เอง** ต้องมีฟอนต์ชื่อ `IBM Plex Sans Thai` น้ำหนัก 400 และ 600 อยู่ในเว็บไซต์แล้ว วิธีที่ใช้คือ Elementor > Custom Fonts (อัปโหลดไฟล์จากโฟลเดอร์ `fonts/`) ถ้าไม่มีฟอนต์นี้ ตัวอักษรจะแสดงด้วยฟอนต์สำรองของระบบ

- **ไฟล์ฟอนต์พร้อมใช้:** โฟลเดอร์ `fonts/` มีไฟล์ WOFF2 ของ Regular (400) และ SemiBold (600) ที่แปลงจากไฟล์ TTF ของ IBM Plex Sans Thai ไฟล์ละประมาณ 40 KB (TTF เดิมไฟล์ละประมาณ 113 KB) ฟอนต์นี้ใช้สัญญาอนุญาต SIL Open Font License อัปโหลดไปที่ Elementor > Custom Fonts ได้เลย ตั้งชื่อฟอนต์ว่า `IBM Plex Sans Thai` และตั้งน้ำหนัก 400 กับ 600
- ตั้งชื่อฟอนต์ใน Elementor ให้ตรงเป๊ะ และใส่ไฟล์ Regular กับ SemiBold ใน **ฟอนต์เดียวกัน** (สอง variation) ถ้าชื่อไม่ตรงหรือไม่มีน้ำหนัก 600 ปุ่มจะบางกว่าดีไซน์หรือเป็นตัวหนาปลอม
- เช็กหลังอัปโหลด: เปิดหน้าเว็บ กด F12 > Network > Font ควรเห็นไฟล์ `.woff2` สองไฟล์จากโดเมนของคุณเอง
- เปลี่ยนไปใช้ฟอนต์อื่นได้โดยตั้ง `--swk-font` ใน `.swk-hero` (ใช้ได้ทั้งข้อความ หัวข้อ ชิป และปุ่ม ทับค่าของ theme)
- ระหว่างรอฟอนต์โหลดอาจแสดงด้วยฟอนต์สำรองของระบบก่อนแล้วสลับ ทำให้ตัวอักษรขยับเล็กน้อย เป็นพฤติกรรมของการตั้งค่า `font-display` ใน Elementor Custom Fonts (ตั้งเป็น `swap` หรือ `optional` ได้) การเก็บไฟล์ไว้ในเซิร์ฟเวอร์ตัวเองซึ่งเป็นวิธีที่ใช้อยู่ช่วยให้โหลดเร็วที่สุด

## ตัวแปรที่ปรับได้ (ใน `.swk-hero`)

| ตัวแปร | ความหมาย | ค่าเริ่มต้น |
|---|---|---|
| `--swk-len` | ระยะ scroll ที่ใช้เล่นแอนิเมชัน | `300svh` (เดสก์ท็อป `500svh`) |
| `--swk-top` | ความสูง header ถ้า header ติด sticky ด้านบน | `0px` |
| `--swk-lead-top` | ตำแหน่งข้อความนำจากขอบบน | ตามอุปกรณ์ |
| `--swk-bottom` | ระยะปุ่มจากขอบล่าง (มือถือและแท็บเล็ต) | `40px` |
| `--swk-accent` | สีปุ่มหลัก | `#126ef5` |

## ปรับแอนิเมชัน (ในส่วน `<script>`)

- `LOGO`: อาร์เรย์ 34x42 ช่อง แก้ได้ทีละช่อง (`.` ว่าง, `#` น้ำเงิน, `+` น้ำเงินอ่อน)
- `LAYOUTS.mobile` / `LAYOUTS.tablet` / `LAYOUTS.desktop`: ขนาดและตำแหน่งโลโก้ (`logoW`, `logoCx`, `logoCy`) วงกลมที่แตกกระจาย (`ring`) พื้นกระเบื้อง (`floor`: จำนวนแถว ขนาด ความเยื้อง สี `mask`) และช่วงเวลาของแต่ละเฟส (`win`: [เริ่ม, สุ่มเริ่มต่อชิ้น, ความยาว] เดสก์ท็อปเป็นวินาที) และช่วงเวลาของแสง glow (`glow`)
- `C_*`: สีอนุภาค, `UI_NAV`, `UI_CARD`, `UI_BROWSER`, `UI_STACK`: ตำแหน่งและขนาด wireframe, `K_*`: สีของ wireframe
- `CURSOR`: เส้นทางเคอร์เซอร์ [วินาที, x, y] และ `CLICKS`: จังหวะและตำแหน่งการคลิก (พิกัดเป็นพิกเซลของพื้นที่ดีไซน์ 1920x1080)
- `LAYOUTS.tablet` สร้างต่อจาก `mobile` แล้วแก้เฉพาะที่ต่าง (โลโก้ ตำแหน่ง `ring` และ `mask` ของพื้น) ปรับตำแหน่ง/ขนาดโลโก้บนแท็บเล็ตที่ `logoW` (ความกว้าง) และ `logoCx` (ตำแหน่งแนวนอน 0-1)

## เรื่อง PageSpeed / SEO

- ข้อความ หัวข้อ ปุ่ม และลิงก์ **อยู่ใน HTML ที่เซิร์ฟเวอร์ส่งมา** ไม่ได้ถูกสคริปต์สร้างทีหลัง Google อ่านได้เหมือนการใช้ widget ของ Elementor
- `h1` เป็นองค์ประกอบ LCP ส่วน canvas ไม่นับเป็นองค์ประกอบ LCP และใส่ `aria-hidden` เพราะเป็นของตกแต่ง
- ไม่มี request เพิ่ม ไม่โหลดฟอนต์และรูปภายนอก (ฟอนต์ใช้ที่ Elementor เก็บไว้ในเซิร์ฟเวอร์ตัวเอง)
- วาดเฉพาะตอน scroll และหยุดเมื่อพ้นจอ (`IntersectionObserver`) จำกัดความละเอียดของ canvas ไม่เกิน devicePixelRatio 2 และไม่เกินราว 4 ล้านพิกเซลต่อเฟรม จอเดสก์ท็อปความละเอียดสูงจึงยังลื่น
- ผู้ใช้ที่เปิด `prefers-reduced-motion` จะเห็นภาพโลโก้นิ่งแทน และความสูง hero ลดเหลือ 1 หน้าจอ
- ถ้าปิด JavaScript ข้อความและปุ่มยังแสดงอยู่

## ข้อควรระวัง

- ปลั๊กอิน cache/optimize (WP Rocket, LiteSpeed, Autoptimize) ที่มีตัวเลือก **Delay JavaScript** ให้เพิ่มข้อยกเว้นให้สคริปต์นี้ (เช่นคำว่า `swk-hero`) ไม่เช่นนั้นแอนิเมชันจะเริ่มช้า การ minify ปกติไม่มีปัญหา (โค้ดใช้ `;` ครบและไม่มีคอมเมนต์ `//`)
- ถ้า theme มี `overflow: hidden` ที่ `body` หรือ wrapper ครอบทั้งหน้า sticky จะไม่ทำงาน ให้ปรับ CSS ส่วนนั้น
- ถ้าเว็บมีหลายภาษา (TH / EN / LO) ข้อความใน HTML widget ต้องแก้ในหน้าแต่ละภาษาเอง ปลั๊กอินแปลภาษาไม่จัดการข้อความใน widget นี้ให้แบบอัตโนมัติเท่ากับ widget มาตรฐานของ Elementor
- เดสก์ท็อปเลื่อนยาว 500svh เพื่อให้เห็นฉาก Nav / Card / หน้าเว็บครบ ถ้าเห็นว่ายาวเกินไป ลดค่า `--swk-len` ในส่วน `@media (min-width: 1024px)`
- บนเบราว์เซอร์เก่าที่ไม่รู้จักหน่วย `svh` จะ fallback เป็น `vh`
- ผลทดสอบทำใน Chromium (จำลองมือถือ แท็บเล็ต และเดสก์ท็อปหลายขนาด) ยังไม่ได้ทดสอบบน Safari จริงหรือบน Elementor จริง และการทดสอบความลื่นทำบนเครื่องที่ไม่มี GPU ควรเปิดดูบนเครื่องจริงก่อนขึ้นเว็บ
